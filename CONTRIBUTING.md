# Contributing

This is the shared contribution flow for Computer MCP repositories. A
repository's own `CONTRIBUTING.md`, where present, adds its build and
verification commands.

1. For a larger change, open an issue first so the approach can be agreed.
2. Branch from `master` and keep the change focused. Add or update tests when
   behavior changes, and update the documentation that owns the behavior.
3. Sign your commits with an SSH or GPG key registered on GitHub.
4. Open a pull request to `master`. Describe the change, its user-visible
   outcome and the checks you ran. Pull requests are squash merged once their
   checks pass.

Do not include credentials, tokens, personal data or private tool output in
issues, pull requests, logs or test fixtures. Contributions are provided under
the license of the repository they are made to.

See [MAINTENANCE.md](MAINTENANCE.md) for versioning, tags and release records.
